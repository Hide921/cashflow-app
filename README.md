# Cashflow

口座・取引・給与・借入・投資を管理する静的Webアプリです。

## 開発と検証

Node.js 22以降で実行します。開発サーバーは `npm install` 後に `npm run dev` で起動します。

```sh
npm run check
```

テストとHTML内JavaScriptの構文検査を行い、配布用ファイルを `dist/` に出力します。検証と静的ビルドには外部パッケージは不要です。GitHub Actionsでもpush・PRごとに同じチェックを実行します。

ブラウザの確認は、PlaywrightとMicrosoft Edgeを利用できる環境で `node scripts/browser-smoke.mjs` を実行します。Playwrightが別の場所にある場合は `PLAYWRIGHT_PATH`、Chromeを使う場合は `BROWSER_CHANNEL=chrome` を指定します。React・React DOMのUMDファイルを `node_modules` から使うため、この検証にはReact 18とReact DOM 18も必要です。実データの代わりに架空の口座・給与を使い、クラウド・価格APIへの通信を遮断します。画面画像はGit管理外の `.artifacts/` に保存します。

## 端末データとアカウント

家計・投資の端末保存先は、ログインしたユーザーIDごとに分かれます。未同期の変更も、そのユーザーにログインし直すまで保持します。別アカウントのログインを検出した画面は再読み込みし、保存時にもユーザーIDを確認します。

旧バージョンの端末データは所有者情報を持たないため、初回に引き継ぎ画面を表示します。表示されたメールアドレスを確認し、自分のデータなら引き継ぎを選択してください。クラウドから始める場合も旧データは削除しません。引き継ぎ画面から旧データの控えをダウンロードできます。この控えは調査・復旧用の保存形式で、通常のJSON復元用バックアップとは異なります。

JSON復元では形式・日付・金額・IDの重複を検証し、現在の内容を変更する前に端末に控えを保存します。「設定 → 前回の復元前データをダウンロード」で取り出せます。投資明細は投資画面の書き出しを使用します。ブラウザの保存領域を消去すると、未同期データと端末内の控えも失われるため、必要な控えはファイルに保存してください。

## 給与の支給日

指定支給日と実際の振込日を分けて保持します。土日・日本の祝日・振替休日・国民の休日は前営業日に調整します。コピーでは指定日、月末払い、翌月払いを引き継ぎます。自動作成した仮給与を元に予測を延長し続けることはありません。

祝日の参照元: [内閣府「国民の祝日」](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)。2020年以降のルールと2020・2021年の特例移動に対応します。将来の春分・秋分日は計算値を使うため、祝日が正式発表されたら照合が必要です。銀行独自の休業日や会社独自の休業日は対象外です。

## 公開前に確認する項目

フロントエンドのテストは、Supabaseの実環境のアクセス制御を保証しません。本番DBについて、別ユーザーの読み書きが拒否されるRLSとキーの一意制約を確認してください。複数データ項目の復元はクラウド側では別々の保存となるため、複数端末が同時に復元・編集する運用にはサーバー側のトランザクション対応が必要です。

現在の画面はReact・Tailwind・SupabaseなどをCDNから読み込みます。新規起動には通信が必要です。一般向け配布の前には依存ライブラリのローカル配信、実端末での確認、認証・同期の実環境試験も行ってください。
